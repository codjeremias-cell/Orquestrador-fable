## Leitura honesta do resultado

Nos dois casos reais e discriminantes (1 e 2), a skill fez diferença clara e na direção certa: o baseline reproduz um padrão Java genérico plausível mas incorreto para o contexto real (pacote errado, injeção por construtor onde o SIGO usa campo direto, exceções de negócio inventadas em vez de citar a convenção real do projeto-alvo), enquanto a versão pós-skill busca e cita a fonte real (`AutenticacaoService` verbatim no caso 1, `CatalogService`/`springboot-repository-service` no caso 2), declara divergências de contexto em vez de escondê-las (RI-01) e marca como suposição explícita o que não pôde confirmar — inclusive no caso 2, onde a pós-skill não acertou 100% (a exceção de "já cancelada" diverge do único exemplo citado), ela foi honesta sobre isso em vez de fingir certeza, o que é o comportamento desejado mesmo sem nota perfeita. O caso 3 não prova nem desprova a skill: é um eval sintético onde o próprio prompt já contém o padrão a copiar, então baseline e pós-skill convergem para a mesma resposta correta — ele serve como controle (mostra que a skill não piora nem introduz ruído onde não é necessária), não como evidência de ganho. Amostra de apenas 3 casos (2 discriminantes) é pequena para conclusão estatística, mas dentro dela o padrão é consistente com a hipótese da skill: ela reduz "padrão genérico plausível" e aumenta "espelhar o projeto real + declarar o que é suposição".
