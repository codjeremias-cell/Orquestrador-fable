## Leitura honesta

O caso 1 (projeto real SIGO) mostra a skill funcionando exatamente como projetada: vira o veredito de vermelho para verde reproduzindo o gabarito real com fidelidade alta, inclusive nos detalhes finos (trava em 2 níveis, proxy de fechamento, chaves de config). O caso 2 é não-discriminante — tanto baseline quanto pos-skill já acertavam o invariante central (não importar o padrão SIGO onde não cabe), então não serve para medir ganho, só para confirmar que a skill não piora um caso que já ia bem. O caso 3 é o mais revelador: é exatamente o ramo que o corpo da skill escreve para evitar — "não copiar cegamente o padrão SIGO em greenfield, declare SUPOSIÇÃO:" — e a execução pos-skill fez o oposto, aplicando o few-shot do SIGO por reflexo e chamando isso de conformidade com RO-01/RI-01. Isso não é falha de baseline (que também é vermelho, por outro motivo: falta de invariantes básicos), é sinal de que o gabarito SIGO tem gravidade forte demais no prompt e pode dominar o julgamento mesmo quando a própria skill pede o caminho simples — vale investigar se a seção "Gabarito SIGO" precisa de um contraponto textual mais explícito para o ramo greenfield sem projeto-irmão.
